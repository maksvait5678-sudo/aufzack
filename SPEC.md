# Deutsch Drill — специфікація проєкту

Статичний сайт для зубріння німецької граматики через інтервальне повторення.
Один рушій, багато тем. Без бекенду, без збірки, без залежностей.

Робоча версія першої теми вже існує (один HTML-файл, `legacy/artikel.html`).
Її треба не переписувати з нуля, а розібрати на рушій + дані.

---

## 1. Обмеження (не порушувати)

- Vanilla JS, ES-модулі, без фреймворків, без npm-залежностей у рантаймі, без збірки.
  GitHub Pages віддає репозиторій як є; `index.html` має працювати при відкритті напряму.
- Без бекенду і без акаунтів. Прогрес — `localStorage`.
- Працює офлайн після першого відкриття.
- Mobile-first, повне керування з клавіатури, темна і світла тема, `prefers-reduced-motion`.
- UI українською. Ідентифікатори в коді англійською.
- Ніякого трекінгу, аналітики, cookie-банерів.

## 3. Рушій інтервального повторення

Рівні 0..8, інтервали:

```
60 с · 1 хв · 10 хв · 1 день · 3 дні · 7 днів · 16 днів · 35 днів · 80 днів
```

Рівні 0 і 1 навмисно однакові: після помилки картка повертається не миттєво.

Стан картки: `{ b: рівень, due: timestamp, r: правильних, w: помилок, relearn?, relearnAt? }`.

Оцінювання відповіді:
- **Помилка** → `b = 0`, `due = now + IV[0]`, `relearn = true`, серія обнуляється.
  Помилка швидша за 1200 мс → додатково `w += 2` (замість `+1`): вгадування не має бути вигідним.
- **Правильно і швидко** (в межах ліміту типу картки) → `b = min(b+1, 8)`, `due = now + IV[b]`.
- **Правильно, але повільно** → `b = max(b, 1)`, рівень не росте, `due = now + IV[b]`.

**Перевчання (`relearn`).** Поки прапорець стоїть, рівень не піднімається вище 2. Щоб його зняти,
картку треба відповісти правильно двічі: перший раз — у межах сесії, другий — не раніше ніж через
10 хвилин після першого. Перша правильна відповідь відкладає наступну появу картки щонайменше на
10 хвилин; друга (після розриву) знімає прапорець, і далі рівень росте як звичайно.

Ліміти швидкості за типом картки: `choice` 4000 мс, `sentence` 7000 мс, `grid` 12000 мс, `type` 12000 мс.

Вибір наступної картки в режимі «Навчання», по порядку:
1. Прострочені картки, крім 6 останніх показаних; сортування: менший рівень → раніший `due`.
2. Нова картка, якщо карток у роботі менше 6. У ліміт рахуються картки рівня ≤ 2, але **не**
   картки з `relearn` — інакше колода забивається картками, які тимчасово не можуть вийти
   з навчання, і нові не вводяться.
3. Дострокове повторення картки з рівнем ≤ 1, крім останніх показаних і **крім карток з `relearn`**
   (дострокова поява ламала б їхнє 10-хвилинне рознесення й давала глухий цикл без прогресу).
4. Нова картка, навіть якщо ліміт у роботі перевищено.
5. Найближча за `due` картка в роботі.

Режим «Профілактика»: випадкова картка з уже відкритих, вага
`1 + (6 - min(b,5))*2 + min(w,5)`. Правильна відповідь на не прострочену картку розкладу не змінює;
помилка діє як у звичайному режимі й повертає картку в чергу.

`srs.js` має бути чистою функцією від стану і часу, без DOM і без `Date.now()` всередині —
час приходить аргументом, щоб його можна було тестувати.

## 4. Типи карток

Тип — це контракт рендеру, а не тема.

- `choice` — запит і 6–8 варіантів-кнопок. Варіанти фіксованого порядку, гарячі клавіші 1..8.
- `sentence` — те саме, але запит це речення з пропуском; після відповіді пропуск заповнюється.
- `grid` — зворотна картка: показано відповідь, треба позначити всі клітинки матриці, де вона стоїть.
- `type` — ввід тексту з клавіатури. Порівняння без урахування регістру; умлаути приймати
  і в формі `ae/oe/ue/ss`. Потрібно для сильних дієслів.

Після помилки завжди показувати правильну відповідь і міні-таблицю теми з підсвіченою клітинкою.
Після правильної відповіді — автоперехід (швидка 750 мс, повільна 1500 мс).

**Другий шар фідбеку (`why`).** Кожна картка може мати необовʼязкове поле `why` — короткий рядок
з правилом, який показується під правильною відповіддю. `why` пояснює *механізм* (чому саме ця
форма), а не повторює відповідь. Якщо для картки неможливо сформулювати таке правило — картка,
найімовірніше, погана. Це найдешевша зміна з найбільшим впливом на навчання.

**Двокрокова картка** (для Wechselpräpositionen) — не новий тип, а послідовність двох наявних
рендерів: спершу вибір `Wo?`/`Wohin?`, після відповіді — звичайний вибір артикля. Обидва кроки
оцінюються; у стані картки зберігається, на якому кроці була помилка (`step1` — не знає правила,
`step2` — не знає таблиці), для діагностики.

## 5. Схема теми

```js
export default {
  id: 'artikel',
  title: 'Артиклі: der, die, das',
  subtitle: 'Відмінки і роди',
  logo: '<span class="tl-word">Artikel</span>…',    // знак теми з її матеріалу (HTML або SVG)
  answers: ['der','die','das','des','dem','den'],   // кнопки, фіксований порядок
  colors: { der:'#16C1E3', die:'#BDF45F', das:'#D3D6DE', des:'#FF6BCB', dem:'#FF6040', den:'#FFB957' },
  matrix: {                                          // для карти засвоєння і міні-таблиці
    rows: [{ k:'nom', label:'Nominativ', hint:'Wer? Was?' }, /* ... */],
    cols: [{ k:'m', label:'maskulin' }, /* ... */],
    value: (row, col) => 'der'
  },
  cards: [ /* згенеровані картки, у порядку введення нових */ ]
}
```

Картка: `{ id, type, prompt, answer, group, cell: {row, col}, why? }`.
`cell` потрібна для карти засвоєння, у карток типу `grid` її немає.
`why` — необовʼязкове правило під правильною відповіддю (див. §4).
`group` — назва блоку введення (наприклад `'Nominativ'`), показується в хабі.
`logo` — знак теми, зроблений з її ж матеріалу (для `artikel` це «Artikel» + пігулки
der/die/das у їхніх кольорах). HTML або SVG.

Порядок карток у масиві = порядок відкриття нових. Тема сама вирішує послідовність.

**Бренд.** `Auf Zack` — бренд **сайту**, не гри. У кожної теми своє `logo` з її матеріалу.
На екрані гри в шапці — лого теми; `Auf Zack` живе тільки в хабі та в маленькій кнопці
повернення в хаб. У хабі кожен рядок теми показує своє `logo` замість текстової назви.
Фавікон і назва застосунку (`<title>`, PWA-manifest) лишаються брендовими — це сайт.
Кольори артиклів — мнемоніка таблиці, не бренд; брендові зелений і чорний — лише інтерфейс
(шапка, режими, хаб, «Далі»); карта засвоєння лишається нейтральною.

## 6. Карта засвоєння

Матриця теми, заливка рівня — **нейтральний колір**, однаковий для всіх клітинок.
Кольори відповідей показуються тільки після натискання «Підглянути таблицю».
Це навмисно: кольорова карта дозволяє вчити візуально замість через питання.

## 7. Прогрес і міграція

```js
{ v: 2, topics: { artikel: { cards: {...}, streak, best, today } }, updatedAt }
```

Обовʼязково: при першому запуску прочитати старий ключ `artikel-srs-v1` і перенести його
в `topics.artikel`, старий ключ не видаляти. Прогрес не повинен губитися при оновленні сайту.

Додати експорт і імпорт прогресу одним текстовим кодом (base64 від JSON), кнопки в налаштуваннях.
Учні змінюють пристрої, і без цього вони втрачають усе.

## 8. Хаб (index.html)

Список тем: назва, коротке пояснення навіщо це вчити, відсоток засвоєння, скільки карток на черзі зараз.
Теми, що спираються на інші, позначені як рекомендовані після них, але не заблоковані.
Кнопка «Продовжити» веде в тему з найбільшою чергою.

## 9. Теми і порядок реалізації

Кожна тема — окремий PR. Наступну починати тільки після мержу попередньої.

**Фаза 1 — рефакторинг.** Розібрати `legacy/artikel.html` на рушій + тему `artikel`.
Поведінка, візуал і прогрес ідентичні legacy. Тести на `srs.js`. Зміни рушія з §3 (перевчання,
штраф за швидку помилку, розширене вікно) застосовуються вже після цієї фази.

**Фаза 2 — `genus`. Рід іменників. (Виконано.)**
Найважливіша тема проєкту. Без роду іменника таблиця артиклів марна: учень знає, що
Dativ feminin це `der`, але не знає, що `Tür` — feminin.
- Картка: іменник → `der`/`die`/`das`. Три кнопки.
- 150–200 найчастотніших іменників рівня A1–A2.
- Групувати за сигналами закінчень: `-ung, -heit, -keit, -schaft, -ion` → die;
  `-er, -ling, -ismus` → der; `-chen, -lein, -um` → das. Спершу група з сигналом, потім винятки.
- `why`: назвати сигнал, якщо він є (`-ung завжди die`), інакше позначити слово як таке,
  що вчиться напам'ять.

**Фаза 3 — `artikel` доповнюється ein-словами.**
`ein/kein/mein` не є окремою темою: це та сама таблиця мінус закінчення в трьох клітинках
(Nom m, Nom n, Akk n). Додати в тему `artikel` блок карток, що відкривається після того,
як der-таблиця досягла рівня 6. Матриця та сама, з другим рядом відповідей.

**Фаза 4 — `praepositionen`. Прийменники.** Найвища віддача на час. Порядок усередині теми:
1. прийменник → відмінок (Akk-група, потім Dat-група);
2. прийменник + артикль у реченні;
3. злиті форми (`zum`, `ins`, `am`, `zur`);
4. Wechselpräpositionen через двокрокову картку;
5. Wechsel через дієслівні пари: stellen/stehen, legen/liegen, setzen/sitzen.

**Ніколи** не формулювати правило як «рух → Akkusativ» (`Ich laufe im Park` — рух, але Dativ).
Критерій — зміна локації, перетин межі; так і писати в `why`. Обовʼязково ставити поруч пари
з однаковою фразою й різним відмінком (`Das Kind spielt auf der Straße` / `... läuft auf die Straße`).

**Фаза 5 — `pronomen`. Особові займенники.**
Одиниця засвоєння — трійка цілком (ich/mich/mir), не окремі форми.
- трансформація: `Ich sehe den Mann → Ich sehe ___` → ihn;
- керування дієслова: `Ich danke ___ (du)` → dir поруч з `Ich frage ___ (du)` → dich;
- порядок слів: вибір з готових речень (`Ich gebe es ihm`), довгі кнопки, не новий тип.
Окремо опрацювати `ihr` — три значення, головне джерело плутанини.

**Фаза 6 — `adjektive`. Відмінювання прикметників.** Останні за пріоритетом.
Вчити не як три таблиці, а як одне правило: у групі рівно один елемент несе ознаку відмінка
й роду. Слабка схема (після der-слів) — база; змішана — як три винятки на фоні слабкої;
сильна — після. Додати діагностичну картку: класифікація детермінатива
(`viele` — немає сигналу, `unsere` — der-слово).

**Фаза 7 — `verben_kasus`, `starke_verben`.** Без змін відносно початкового плану, але після всього.

## 10. Перетини тем

**Обовʼязкові:**
- прийменник + артикль — у цьому сенс теми прийменників;
- прийменник + займенник: `mit ___ (ich)` → mir;
- прикметник + артикль.

**Заборонені на етапі вивчення:**
- прийменник + прикметник + артикль в одній картці: три невідомі — помилку не діагностувати
  (дозволено лише коли обидві теми на рівні 7+);
- Wechselpräposition + прикметник — ніколи: два правила виведення в одній картці перетворюють
  відповідь на вгадування.

## 11. Межі тренажера

Записано чесно, щоб не створювати ілюзій (продубльовано в README):
- продукцію в мовленні: учень з 95% на картках у розмові все одно скаже `ein gute Mann` —
  там немає двох секунд на роздуми;
- порядок слів у складному реченні;
- вибір прийменника там, де можливі кілька (`nach`/`zu`/`in`);
- дієслівне керування з прийменниками (`warten auf`) — це лексика дієслова, окремий модуль.

Тренажер закриває автоматизм форм. Усе інше добирається розмовною практикою.

## 12. Правила щодо змісту

Німецькі дані — не імпровізація. Перед комітом теми звірити кожну форму з довідником
і винести дані в окремий файл, щоб їх міг перевірити вчитель. Якщо в якійсь формі є сумнів —
не вигадувати, а позначити `// TODO: перевірити` і сказати про це в описі PR.
Одна помилкова форма в грі про зубріння шкідливіша за відсутню тему.

## 13. Критерії готовності фази

- Працює при відкритті `index.html` з файлової системи і на GitHub Pages.
- Прогрес попередніх тем не зламався.
- `node --test` зелений.
- Перевірено на ширині 360 px і на клавіатурі без миші.
- Жодної нової залежності.
